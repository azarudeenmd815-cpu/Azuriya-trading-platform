## Truthful product boundaries

### Team and communication workspace

The dashboard's Community view uses a themed communication layout with categorized text channels, direct conversations, voice rooms, a central message feed and member presence. Annotated chart attachments, pinned context and threads give the messages useful visual structure. Search, reactions, pins, local messages and replies, session polls, example attachments, channel notification preferences, channel creation, event RSVPs, community role drafts and moderation previews are interactive. Voice join, mute, deafen and screen sharing show simulated states without requesting microphone access or starting a call.

Teams connects the member directory to the selected trading group, with name and presence filters, local role assignments, a capability matrix, shared resources, an invitation example and event interest. Permission drafts are stored separately for each team. Resource links open their stated channel and pinned context. The Overview adds a compact weekly communication dot histogram and working shortcuts into Teams and Community. Blue dots represent voice activity; theme text-colored dots represent text activity. One full dot represents two participants, with half dots for odd counts and accessible daily values. The volume chart uses six rounded blue horizontal bars, lavender previous-period comparisons, a numeric axis and vertical grid lines. Its precomputed illustrative bins reconcile to the selected team and period. Summary cards use smooth trend curves instead of angular area charts. The four financial summary cards remain exclusive to Overview. Conversation and thread drafts, attachments and poll selections survive navigation during the current visit; these local previews do not send invitations, change authenticated account ownership or publish messages to a backend.

All new settings are demonstration drafts. Review actions show local configuration summaries and never apply server changes, execute trades or move funds. Required authentication, account ownership, order validation, risk enforcement and append-only records are fixed safeguards. Financial displays use decimal strings and precomputed fixtures or exact integer presentation arithmetic. SVG coordinates and plotted bar widths may use floats.

All portal dashboards, funding, chat and admin settings are labelled illustrative. Copy toggles affect only the local demonstration. Current execution remains simulated. Account creation uses the existing versioned authenticated API. Pricing examples do not imply guaranteed earnings. The screenshots are infrastructure references; their latency or connection statuses are not represented as current Azuriya measurements. Every supplied image remains available unchanged. LP logos identify supplied options, and platform logos come from official websites. No fabricated client logos, testimonials or implemented connector claims.

The MT5 deposits page is a feature explanation, not a live checkout. Native funding requires broker-enabled payments and a configured payment provider. Checkout uses the provider's payment flow, and account credit follows successful processing and broker approval. Currencies, methods, fees and processing times depend on provider terms and broker settings. The local walkthrough changes only illustrative steps. It collects no card data and makes no payment requests. Reference images contain example account details; the supplied screenshot containing a credential is excluded from public assets.
