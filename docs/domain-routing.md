# Domains and provider contract

A hostname binds organization, brand, environment, product instance and application purpose. Host context never grants permission. Membership/scoped credentials are checked independently. Customer hosts reject Core, wrong-instance and wrong-portal APIs; unknown hosts return 421. Trusted HTTP redirects with 308 to the validated HTTPS origin. Sessions are host-only and also bind to the exact originating hostname in the database.

Registration normalizes IDNA/ASCII names and rejects schemes, ports, wildcards, IPs, malformed labels and duplicate bound hosts. A random TXT challenge expires after 24 hours. Verification resolves real DNS with a five-second timeout and requires joined TXT chunks to match exactly. Checked timestamps/safe failure codes persist. Expiry, token and version checks fence slow verification/rotation/disable races. Rotation immediately invalidates routing eligibility.

The operator deploys an authenticated HTTPS service at DOMAIN_PROVIDER_URL. PUT `/v1/hostnames/<id>` receives hostname, canonical tenant IDs, application type, verified_at and existing certificate reference. Idempotency keys are `<id>:<challenge-version>:PUT`. Responses contain matching hostname; ssl_status pending/requested/validating/issued/renewing/active/failed/revoked; edge_status pending/active/failed; safe certificate_issuer, certificate_reference, certificate_expires_at, edge_reference and optional dns_target/error_code. Active requires issuer, provider references, future expiry and confirmed edge routing. Acceptance alone is not active evidence. SSL active with edge pending is recorded as issued. Private certificate keys stay at the provider. DELETE removes/revokes delivery idempotently.

Worker scheduling uses an advisory lock; delivery checks run under durable outbox leases. Verified pending/failed domains poll at least five minutes apart; active certificates within 30 days of expiry enter renewal checks. Challenge versions fence stale jobs. Disabled/rotated domains enqueue cleanup retries. Local routing stops immediately even when provider cleanup fails. Failed renewal fails closed, so provider latency affects availability.

Controlled tests cover four tenant hostnames, separate branding/portal context and lifecycle failures. Public DNS, four trusted certificates, actual bridge/edge deployment and public browser sessions remain unverified until resources are supplied. Fixture metadata is never operational certificate proof.
