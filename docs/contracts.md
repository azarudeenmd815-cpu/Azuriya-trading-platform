# Internal implementation contract

All JSON API entities use snake_case fields. Shared input types are in `src/shared/types.ts`. No secrets in Row lists.

## Database (database agent)

`src/server/db/database.ts` exports `Executor` with `query<T>(sql: string, params?: unknown[]): Promise<{rows:T[]}>`, `Database extends Executor` with `transaction<T>(context: {core?:boolean;organizationId?:string}, work:(tx:Executor)=>Promise<T>):Promise<T>`, `close():Promise<void>`, and `createDatabase(options?:{dataDir?:string;url?:string}):Promise<Database>`. `src/server/db/migrate.ts` exports `migrate(db:Database):Promise<void>`. Migrations live in `migrations` and are copied/resolved from repository root at runtime. Runtime always uses the non-superuser `azuriya_app` role, even locally, with transaction-local RLS context; setup uses owner connection. `src/server/db/seed.ts` exports `seedCatalog(db):Promise<void>`.

## Services (domain agent)

`src/server/domain/service.ts` exports `FoundationService`, constructed with `Database`. Methods: `coreList(resource:string, query:ListQuery):Promise<Page>`, `tenantList(actor:TenantContext,resource:string,query:ListQuery):Promise<Page>`, `overview(actor:Actor):Promise<Row>`, `createOrganization(actor:Actor,input:OrganizationInput):Promise<Row>`, `provision(actor:Actor,input:ProvisionInput):Promise<Row>`, `branding(actor:TenantContext):Promise<Row>`, `updateBranding(actor:TenantContext,input:BrandConfig):Promise<Row>`, `createDomain(actor:TenantContext,input:DomainInput):Promise<Row>`, `verifyDomain(actor:TenantContext,id:string):Promise<Row>`, `disableDomain(actor:TenantContext,id:string):Promise<Row>`, `requestIntegration(actor:TenantContext,input:IntegrationRequestInput):Promise<Row>`, `triageRequest(actor:Actor,id:string,input:{status?:string;assigned_to?:string;internal_notes?:string;priority?:string}):Promise<Row>`, `createApiKey(actor:TenantContext,input:ApiKeyInput):Promise<{key:Row;secret:string}>`, `revokeApiKey(actor:TenantContext,id:string):Promise<Row>`, `addStaff(actor:TenantContext,input:StaffInput):Promise<Row>`, `createRole(actor:TenantContext,input:RoleInput):Promise<Row>`, `createWebhook(actor:TenantContext,input:WebhookInput):Promise<Row>`, `setFeatureFlag(actor:Actor,input:{key:string;enabled:boolean;description?:string}):Promise<Row>`. Actor carries trusted context; services enforce permission/core themselves too. Audit mutations are atomic with outbox inserts. `src/server/domain/errors.ts` exports `AppError(statusCode:number,code:string,message:string,details?:unknown[])`. Domain verification is real DNS TXT only; SSL/edge absent means no active domain.

## Schema convention

UUID IDs are generated by application `crypto.randomUUID()`. Timestamps are `timestamptz default now()`. Standard columns: organizations(name,slug,business_type,status), brands(organization_id,name,config jsonb), environments(organization_id,brand_id,name,kind,status), products(slug,name,description,status,modules jsonb), product_subscriptions(organization_id,product_id,plan,status,limits jsonb), product_instances(organization_id,brand_id,environment_id,subscription_id,product_id,name,status,config jsonb). users(email,password_hash,display_name,core_role nullable,status,mfa_required boolean); sessions(user_id,token_hash,csrf_hash,expires_at,last_seen_at). roles(organization_id,name), permissions(code), role_permissions(role_id,permission_code,organization_id). staff_memberships(organization_id,user_id,role_id,environment_id nullable,product_instance_id nullable,status); client_memberships(organization_id,user_id,product_instance_id,status). Membership constraints bind tenant and scope. domains(organization_id,brand_id,environment_id,product_instance_id,hostname,application_type,verification_token,verification_method,status,ssl_status,is_primary,dns_target,verified_at,last_checked_at,failure_information,redirect_config jsonb). integration_providers(name,slug,category,description,status,connection_mode,supported_products jsonb,managed boolean,connector_available boolean); integration_provider_capabilities(provider_id,capability); integration_connections(scope ids,provider_id,status,credential_reference,last_checked_at,error); integration_requests(scope ids,provider_name,website,category,current_provider,notes,connection_target,status,assigned_to,internal_notes,priority). api_keys(scope ids,name,prefix,secret_hash,scopes jsonb,expires_at,revoked_at,last_used_at,created_by,application_id nullable); api_applications(scope ids,name,status); service_accounts(scope ids,name,status); webhook_endpoints(scope ids,name,url,events jsonb,status,signing_secret_reference); audit_events(organization_id nullable,brand_id nullable,environment_id nullable,product_instance_id nullable,actor_id,action,resource_type,resource_id,request_id,metadata jsonb); outbox_events(organization_id nullable,event_type,payload jsonb,published_at). feature_flags(key,enabled,description). Include oauth_clients, webhook_deliveries, tenant_feature_overrides, support_access_grants and idempotency_records foundations. Service agent may add columns but must notify API agent.

## HTTP/UI (root and UI agents)

Responses are `{data: ...}` except lists which are Page, keys `{data:{key,secret}}`, errors `{error:{code,message,details,request_id}}`.

Auth: POST `/api/v1/auth/login` `{email,password}` returns `{data:{user:{id,email,display_name,core_role},csrf_token}}` and HttpOnly cookie; GET `/api/v1/auth/me` returns same plus `memberships:Row[]`, `client_memberships:Row[]`; POST `/api/v1/auth/logout` requires `X-CSRF-Token`. All session mutations require CSRF header. Core endpoints `/api/v1/core/overview`, GET `/core/:resource`, POST `/core/organizations`, POST `/core/product-instances`, PATCH `/core/integration-requests/:id`, PUT `/core/feature-flags/:key`. Resource names: organizations, brands, environments, products, product-instances, domains, integration-providers, integration-connections, integration-requests, api-applications, api-keys, oauth-clients, service-accounts, webhook-endpoints, staff, roles, audit-events, feature-flags, support-access-grants. White Labels uses brands.

Tenant endpoints `/api/v1/instances/:instanceId/context` returns `{data:{organization,brand,environment,instance,product,permissions}}`; `/overview`; GET `/branding`, PATCH `/branding`; GET/POST `/domains`; POST `/domains/:id/verify`, DELETE `/domains/:id`; GET `/integrations` (shared product-filtered catalog), GET `/integration-connections`; GET/POST `/integration-requests`; GET/POST `/staff`; GET/POST `/roles`; GET/POST `/api-keys`, DELETE `/api-keys/:id`; GET/POST `/webhooks`; GET `/audit`; GET `/settings`. Tenant mutations use types above. Context is resolved from membership, never body IDs. Core logins use Core routes; tenant staff use tenant routes. Client GET `/api/v1/client/instances/:instanceId/context` uses separate client_memberships and returns branding/instance/product/profile. GET `/api/v1/client/profile` returns current own safe user fields. Runtime and UI do not create fixture tenants automatically.

Frontend routes `/login`, `/core/:section`, `/admin/:instanceId/:section`, `/portal/:instanceId/:section`; section defaults overview. Browser API requests same-origin with credentials. Show exact `100+ One-Click Integrations` header for both CRM instances, explain only actual seeded catalog entries are currently listed and external connectors are request-only. Login needs normal credentials configured through bootstrap. Core creates organization with optional existing owner email; staff membership can be assigned to a previously registered user. Root provides CLI for user creation.
